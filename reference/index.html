    API reference

    Generated from the docstrings in the code.

    Read and write volumes as OME-Zarr, keeping their physical metadata.

    OME-Zarr (also called NGFF) is the community format for large bioimaging data. Reading is lazy: you get a dask array, and voxels are only loaded from disk when a calculation needs them, so volumes larger than memory still work.

    Volume dataclass

    Image or label data together with the metadata needed to interpret it.

    Keeping voxel size and units next to the data means measurements can be reported in physical units, and the metadata is not lost when results are written back out.

    Parameters:

    Name Type Description Default
    data Array or ndarray

    Voxel values, with axes in the order given by dims.

    		 required
    dims tuple of str

    Axis names, e.g. ("z", "y", "x").

    		 required
    voxel_size dict of str to float

    Size of one voxel along each spatial axis, in unit.

    		 required
    unit str

    Physical unit of voxel_size, as an OME-Zarr unit name such as "nanometer".

    		 'nanometer'
    name str

    Short name stored in the OME-Zarr metadata.

    		 'image'

    read_ome_zarr(path, level=0)

    Open one resolution level of an OME-Zarr image without loading it.

    Parameters:

    Name Type Description Default
    path str or Path

    Local path or URL of the .ome.zarr store.

    		 required
    level int

    Pyramid level, where 0 is full resolution and higher levels are progressively downsampled.

    		 0

    Returns:

    Type Description
    Volume

    Lazy (dask) data with the voxel size and unit of that level.

    write_ome_zarr(volume, path, scale_factors=None, labels=False)

    Write a volume as OME-Zarr with a multiscale pyramid.

    Parameters:

    Name Type Description Default
    volume Volume

    Data and metadata to write.

    		 required
    path str or Path

    Destination .ome.zarr path. It must not already exist.

    		 required
    scale_factors list of int

    Downsampling factor of each extra pyramid level relative to full resolution, e.g. [2, 4]. By default one level per halving until the image is small.

    		 None
    labels bool

    Set to True for segmentations, so downsampling keeps label values rather than averaging them into values that are not labels.

    		 False

    Measurements on segmented volumes, in physical units.

    object_volumes(labels)

    Physical volume of every labelled object.

    Works chunk by chunk on dask arrays, so the label image never has to fit in memory.

    Parameters:

    Name Type Description Default
    labels Volume

    Integer label image where 0 is background and each other value is one object. Must have z, y and x voxel sizes.

    		 required

    Returns:

    Type Description
    dict of int to float

    Object label mapped to its volume in cubic labels.unit, e.g. nm³ for "nanometer". Background (0) is not included.

    Examples:

    >>> import numpy as np
>>> cube = np.zeros((4, 4, 4), dtype=np.uint8)
>>> cube[:2, :2, :2] = 1
>>> object_volumes(Volume(cube, ("z", "y", "x"), {"z": 10, "y": 5, "x": 5}))
{1: 2000.0}

    Record how an output was produced, so results can be traced and reproduced.

    A provenance file sits next to each output and records the software version, the parameters and the inputs. For sharing complete datasets, the CCP-volumeEM guide recommends packaging this information as an RO-Crate (https://www.researchobject.org/ro-crate/); this simple JSON record is a starting point that can be converted later.
